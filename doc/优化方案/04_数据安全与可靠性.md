# 04 — 数据安全与可靠性

> **状态**：设计方案，未实现；基线 `b35d1a2`；当前事实 = 静态代码证据，指标 = 拟定验收目标

## 核心安全原则（贯穿全文档）

1. **删除默认可撤销** — 所有删除操作走回收站，永久删除需额外二次确认
2. **批量操作可取消** — 任何 >1 项的批量操作必须提供进度报告和取消能力
3. **路径不越权** — 文件操作受沙箱约束，拒绝系统关键路径和路径穿越
4. **Agent 不自动执行破坏性操作** — AI/Agent 只能建议，用户确认后才执行

## 4.1 危险操作二次确认与可撤销

### 当前状态

| 操作 | 确认机制 | 可撤销 | 证据 |
|------|----------|--------|------|
| 移入回收站（单项） | Modal.confirm ✓ | ✓ trash restore | App.tsx handleDelete |
| 移入回收站（批量） | Modal.confirm ✓ | ✓ 逐项可恢复 | App.tsx L934-948 |
| 永久删除 | Modal.confirm + danger ✓ | ✗ 不可逆 | App.tsx L956-970 |
| 清空回收站 | Modal.confirm ✓ | ✗ 不可逆 | TrashModal |
| 批量重命名 | 预览表 ✓ | ✗ 无 undo | BatchRename.tsx |
| 移动文件（拖拽） | 无确认 | ✗ 无 undo | DragDropMove.tsx |
| 覆盖文件（粘贴同名） | 无确认 | ✗ 数据丢失 | App.tsx handlePaste |

### 改造方案

**P0 — 必须立即修复**：
1. `delete_file` 命令增加 `validate_path()` 前置校验（见 4.2）
2. 永久删除增加**输入确认**（类似 GitHub 删除仓库：输入文件名才能确认）
3. 拖拽移动增加 toast 提示 + "撤销" 按钮（5s 内可点击 undo）

**P1 — 近期改造**：
4. 引入全局 Undo Stack（最近 50 步操作）
5. 粘贴同名文件时弹出冲突对话框：覆盖 / 跳过 / 保留两者（自动加后缀）
6. 批量重命名前自动创建 undo 快照

## 4.2 路径穿越 / 越权防护

### 当前威胁模型

```
攻击向量 1: 前端 invoke("delete_file", { path: "/" })
攻击向量 2: 符号链接 /tmp/evil -> /etc，invoke("delete_file", { path: "/tmp/evil" })
攻击向量 3: 路径穿越 invoke("read_file_content", { path: "../../.ssh/id_rsa" })
攻击向量 4: assetProtocol scope ["**"] 允许 WebView 加载任意本地文件
```

### 防护方案 — `path_guard.rs` 模块

```rust
// 规划新增文件：src-tauri/src/path_guard.rs
pub struct PathGuard {
    allowed_roots: Vec<PathBuf>,       // 用户显式授权的根目录
    blocked_paths: Vec<PathBuf>,       // 绝对禁止的路径
    follow_symlinks: bool,             // 是否跟随符号链接（默认 true）
}

impl PathGuard {
    /// 校验路径是否允许操作
    pub fn validate(&self, raw_path: &str) -> Result<PathBuf, PathError> {
        let path = PathBuf::from(raw_path);
        
        // 1. 拒绝空路径和相对路径
        if !path.is_absolute() {
            return Err(PathError::RelativePath);
        }
        
        // 2. Canonicalize（解析符号链接和 ..）
        let canonical = path.canonicalize()
            .map_err(|_| PathError::NotFound)?;
        
        // 3. 检查黑名单
        for blocked in &self.blocked_paths {
            if canonical.starts_with(blocked) {
                return Err(PathError::Blocked);
            }
        }
        
        // 4. 检查白名单（至少在一个 allowed_root 下）
        if !self.allowed_roots.is_empty() {
            let in_scope = self.allowed_roots.iter()
                .any(|root| canonical.starts_with(root));
            if !in_scope {
                return Err(PathError::OutOfScope);
            }
        }
        
        Ok(canonical)
    }
}

// 默认黑名单
const BLOCKED: &[&str] = &[
    "/", "/etc", "/usr", "/bin", "/sbin", "/var", "/System",
    "/Library", "/private", "/dev", "/proc", "/sys",
];
```

**集成点**：所有接受 `path` 参数的 `#[tauri::command]` 在函数入口调用 `PathGuard::validate()`。

**allowed_roots 管理**：
- 首次启动时默认为 `dirs::home_dir()`
- 用户通过"打开文件夹"对话框选择的目录自动加入
- 存储在 `app_config_dir/allowed_roots.json`

## 4.3 权限与只读模式

### 当前状态
- `capabilities/default.json` 授予 `fs:default` + `shell:default`（全权限）
- `tauri.conf.json` CSP=null，assetProtocol scope=["**"]
- 无只读模式概念

### 改造方案

**P0 — Tauri 权限收敛**：
```json
// 规划修改：src-tauri/capabilities/default.json
{
  "permissions": [
    "core:default",
    "clipboard-manager:default",
    "dialog:default",
    {
      "identifier": "fs:allow-read-dir",
      "allow": [{ "path": "$HOME/**" }, { "path": "$APPDATA/**" }]
    },
    {
      "identifier": "fs:allow-read-file",
      "allow": [{ "path": "$HOME/**" }]
    },
    {
      "identifier": "fs:allow-write-file",
      "allow": [{ "path": "$HOME/**" }, { "path": "$APPDATA/**" }]
    },
    "shell:allow-open"
  ]
}
```

**P0 — CSP 启用**：
```json
// 规划修改：src-tauri/tauri.conf.json
"security": {
  "csp": "default-src 'self'; img-src 'self' asset: https://asset.localhost; media-src 'self' asset: https://asset.localhost; style-src 'self' 'unsafe-inline'",
  "assetProtocol": {
    "scope": ["$HOME/**", "$APPDATA/**"]
```

**P1 — 只读模式**：
- 设置中增加"只读模式"开关
- 启用后：所有写操作（删除/移动/重命名/创建）的 Tauri 命令返回 `Err(ReadOnlyMode)`
- 前端按钮置灰 + tooltip 提示

## 4.4 大文件与二进制安全处理

### 当前问题

| 场景 | 问题 | 风险 |
|------|------|------|
| `read_file_content` 10MB 限制 | 超限时返回错误文本，前端可能当 text 渲染 | 内存溢出 |
| `compress_to_zip` read_to_end | 2GB 文件直接 OOM | 进程崩溃 |
| `secure_delete_file` 分配等大 buffer | 1GB 文件需 1GB 内存 | OOM |
| `diff_files` O(m×n) DP | 10000 行 × 10000 行 = 400MB | OOM |
| 二进制检测（前 1024 字节含 \x00） | UTF-16/UTF-32 文件误判为二进制 | 功能缺失 |

### 改造方案

1. **流式处理**：所有文件 IO 使用 64KB 缓冲区分块读写，恒定内存
2. **大小预检**：操作前 `metadata.len()` 检查，超阈值（如 >500MB）提示用户确认
3. **分片预览**：文本文件只加载前 1MB，提供"加载更多"按钮
4. **二进制检测增强**：使用 `content_inspector` crate 或 BOM 检测 + 字节分布分析
5. **Diff 算法替换**：使用 `similar` crate 的 Myers 实现，内存 O(N)

## 4.5 持久化原子写

### 当前状态

| 数据 | 写入方式 | 安全性 |
|------|----------|--------|
| `tags.json` | tmp + rename ✓ | 原子，安全 |
| `library.json` | `fs::write()` 直接覆盖 ✗ | 崩溃可损坏 |
| `file_index.json` | `fs::write()` 直接覆盖 ✗ | 崩溃可损坏 |
| `content_index.json` | `fs::write()` 直接覆盖 ✗ | 崩溃可损坏 |
| bookmarks | localStorage | 浏览器保证，基本安全 |
| tabs/viewMode | 无持久化 | 刷新丢失 |

### 改造方案

统一使用 `atomic_write.rs` 工具函数：

```rust
// 规划新增：src-tauri/src/atomic_write.rs
pub fn atomic_write_json<T: Serialize>(path: &Path, data: &T) -> Result<()> {
    let tmp = path.with_extension("tmp");
    let json = serde_json::to_string_pretty(data)?;
    fs::write(&tmp, &json)?;
    fs::rename(&tmp, path)?;  // 原子操作（同文件系统）
    Ok(())
}
```

所有 JSON 持久化统一调用此函数。`tags.rs` 已有此模式，推广到 `library.rs` 和 `indexer.rs`。

## 4.6 Agent 不可自动执行破坏性操作

### 当前风险

- `execute_command` 可执行任意 shell 命令
- `run_shell_command` 可启动任意程序
- AI Agent（未来实现后）可能调用这些命令

### 安全边界设计

```
┌─────────────────────────────────────────┐
│  AI Agent (FileAgent)                    │
│  ├─ 可调用: read_file_content,          │
│  │          list_directory, search,      │
│  │          get_file_info, compute_hash  │
│  ├─ 仅建议: move, rename, delete, copy  │
│  │          → 生成 OperationPlan         │
│  │          → 展示给用户确认             │
│  └─ 禁止调用: execute_command,          │
│               run_shell_command,         │
│               permanent_delete,          │
│               empty_trash,               │
│               secure_delete_file         │
└─────────────────────────────────────────┘
```

**实现方式**：
1. Agent 命令调用经过 `AgentPermissionFilter` 中间层
2. 白名单内的只读操作直接执行
3. 写操作生成 `OperationPlan`，前端展示 diff 预览 + 确认按钮
4. 用户点击"执行"后才真正调用 Tauri 命令
5. `execute_command` / `run_shell_command` 从 Agent 可调用列表中**永久排除**

### execute_command 改造

**P0 — 立即**：
- 添加命令白名单：仅允许 `open`, `pbcopy`, `pbpaste`, `say`, `afplay`
- 或直接移除该命令，内置终端改用 `tauri-plugin-shell` 的 `Command::new().spawn()`

**P1 — 近期**：
- 内置终端走独立 PTY 进程，不经过 `execute_command`
- 终端内命令由用户直接输入，不暴露为 IPC 命令
