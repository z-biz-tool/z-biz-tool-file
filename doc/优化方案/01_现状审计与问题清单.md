## 已确认缺陷（源码直接可证）

### SEC-01 · Shell 命令执行无任何限制 — P0

`execute_command` 直接将用户输入拼接为 `sh -c`：

```rust
// ../../src-tauri/src/commands.rs L1317-1336
Command::new("sh").arg("-c").arg(command).output()
```

`run_shell_command` 同样接受任意程序路径与参数，仅做 `{path}` 占位替换。  
**风险**：恶意前端代码/XSS 可执行 `rm -rf /`、窃取密钥。

### SEC-02 · `delete_file` 无路径安全校验 — P0

```rust
// ../../src-tauri/src/commands.rs L259-273
pub fn delete_file(path: &str) -> Result<(), String> {
    let file_path = Path::new(path);
    if file_path.is_dir() { fs::remove_dir_all(file_path) }
    else { fs::remove_file(file_path) }
}
```

无 canonicalize、无沙箱根目录限制、无系统关键路径黑名单。  
对比 `trash.rs` 中 `is_path_safe` 阻止了根目录删除 — `delete_file` 缺失同等保护。

### SEC-03 · CSP 完全禁用 + assetProtocol scope `["**"]` — P0

```json
// ../../src-tauri/tauri.conf.json
"security": { "csp": null, "assetProtocol": { "scope": ["**"] } }
```

等于允许 WebView 加载任意本地/远程资源，配合 SEC-01 构成完整攻击链。

### SEC-04 · Tauri capabilities 过宽 — P1

```json
// ../../src-tauri/capabilities/default.json
"permissions": ["core:default","clipboard-manager:default","dialog:default","fs:default","shell:default"]
```

`fs:default` 和 `shell:default` 在 Tauri 2 中为全权限通配；应改为细粒度 scope。

### PERF-01 · 目录列表无分页/虚拟化后端支持 — P1

`list_directory` 同步 `read_dir` 后全量返回 Vec<FileEntry>。数万文件目录（如 `node_modules`）会阻塞 IPC 数秒。  
前端 Table 虽有 `virtual` 属性，但 IPC 传输本身是瓶颈。

### PERF-02 · `compress_to_zip` 将文件整体读入内存 — P1

```rust
// ../../src-tauri/src/commands.rs L813-814
let mut buf = Vec::new();
file.read_to_end(&mut buf)?;
```

对 2GB 视频文件会直接 OOM。应使用 `zip` crate 的流式写入。

### PERF-03 · `diff_files` O(m×n) 动态规划 — P1

```rust
// ../../src-tauri/src/commands.rs L1818-1913
let mut dp = vec![vec![0u32; n + 1]; m + 1];
```

对 10000 行文件将分配 ~400MB 内存。应替换为 Myers O(ND) 或 patience diff。

### REL-01 · 索引器使用相对路径持久化 — P0

```rust
// ../../src-tauri/src/indexer.rs L10
const INDEX_DIR: &str = "index";
```

CWD 取决于启动方式（Finder 双击 vs 终端），索引可能写入不可预期位置且每次不同。

### REL-02 · `library.rs` 非原子写入 — P1

```rust
// ../../src-tauri/src/library.rs L130
fs::write(&p, json)
```

进程崩溃或断电可导致 `library.json` 被截断损坏。对比 `tags.rs` 已正确使用 tmp+rename 原子模式。

### REL-03 · 批量操作无取消机制 — P1

前端逐个 `await invoke("delete_to_trash")` 串行执行：
```typescript
// ../../src/App.tsx L940-948
for (const r of records) { await invoke("delete_to_trash", { path: r.path }); }
```
无 AbortController、无进度上报、无法中途取消。

### ARCH-01 · `aiService.ts` 调用 8 个未注册命令 — P1

`ai_semantic_search`、`ai_categorize_file`、`ai_batch_categorize`、`ai_get_summary`、`ai_suggest_batch_rename`、`ai_get_related_files`、`ai_intelligent_organization`、`ai_suggest_tags` 均未在 `lib.rs` 的 `invoke_handler` 中注册。运行时必定 panic/error。

### ARCH-02 · AgentManager 为 SQL Agent 存根 — P2

```typescript
// ../../src/agent/AgentManager.ts — 全部方法为 TODO 硬编码
```
从 z-biz-tool-db 项目复制，与文件管理功能无关，增加包体积且误导。

### ARCH-03 · App.tsx 单体 2249 行 40+ useState — P1

所有视图逻辑、状态、回调集中在一个函数组件中。可维护性极差，任何改动都可能引入回归。

### ARCH-04 · 双重 file-change 事件订阅 — P2

```typescript
// ../../src/App.tsx L303-327 — useEffect #1
// ../../src/App.tsx L462-509 — useEffect #2（含 debounce）
```
两处均 `listen("file-change", ...)`，导致 watcher 事件被处理两次、可能重复 loadDirectory。

### ARCH-05 · 硬编码用户路径 — P2

```typescript
// ../../src/App.tsx L448
const defaultPath = "/Users/zifang";
```
```typescript
// ../../src/App.tsx L2188
initialPath={currentPath || "/Users/zifang"}
```
其他用户首次启动直接报错或进入不存在路径。
