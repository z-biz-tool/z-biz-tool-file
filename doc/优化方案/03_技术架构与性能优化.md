## 推荐方案（非选项，为明确结论）

### 3.1 大目录（数万文件）— 后端分页 + 流式传输

**问题**：`list_directory` 同步全量返回，10000+ 文件目录 IPC 序列化耗时 >2s。

**方案**：
1. 后端新增 `list_directory_paged(path, offset, limit, sort_by, sort_order)` 命令
2. 首次返回前 200 条 + total_count，前端虚拟滚动触发 `loadMore`
3. 对 >5000 条目录启用 `ReadDir` 流式迭代器，避免一次性 collect
4. 前端 Table `virtual` 已启用，配合 `onScroll` 触发增量加载

**验收目标**：10000 文件目录首次渲染 <300ms（假设 SSD，排除文件系统缓存冷启动）

### 3.2 异步 IO 与取消

**问题**：所有文件操作为同步阻塞 `#[tauri::command]`，大文件复制/压缩期间 UI 无响应且不可取消。

**方案**：
1. 耗时命令改为 `async fn` + `tauri::async_runtime::spawn_blocking`
2. 引入 `tokio_util::sync::CancellationToken`，存储在 `State<HashMap<String, CancellationToken>>`
3. 每个长时间操作返回 `operation_id`，前端可调 `cancel_operation(id)`
4. 循环体中每处理 N 条检查一次 `token.is_cancelled()`

**IPC 契约新增**：
```typescript
// 前端 → 后端
invoke<OperationHandle>("batch_operation", { 
  operation: "move_to_trash" | "copy" | "move" | "delete" | "compress",
  paths: string[],
  options?: { conflictStrategy?: "overwrite" | "skip" | "rename" }
})
// 返回: { operationId: string, total: number }

// 后端 → 前端（Event）
"operation-progress" => { operationId, current, total, currentItem, speed_bps? }
"operation-complete" => { operationId, success, errors[] }
"operation-cancelled" => { operationId, completedBeforeCancel }

// 前端 → 后端
invoke("cancel_operation", { operationId })
```

**验收目标**：1000 文件批量移动可随时取消，取消后 ≤500ms 停止处理

### 3.3 路径解析与符号链接

**问题**：`delete_file`、`move_file`、`copy_file` 不做 canonicalize，符号链接可能导致操作逃逸到沙箱外。

**方案**：
1. 新增 `path_guard.rs` 模块，导出 `validate_path(raw: &str) -> Result<PathBuf, PathError>`
2. 逻辑：`canonicalize()` → 检查是否在允许的根目录下 → 拒绝 `/`, `/etc`, `/System`, `~/.ssh` 等
3. 符号链接策略：默认跟随（与 Finder 一致），但验证 resolved path 仍在安全范围内
4. 所有 `#[tauri::command]` 文件操作入口处统一调用

**验收目标**：构造 `../../etc/passwd` 形式的符号链接攻击路径，100% 被拒绝

### 3.4 跨平台差异

**问题**：
- `set_file_tags` 依赖 `python3` + `mdls` + `xattr`（仅 macOS）
- `run_shell_command` 用 `open`/`explorer`/`xdg-open` 硬编码分支
- 路径分隔符未统一处理（`currentPath + "/" + name`）

**方案**：
1. 标签系统抽象为 trait `TagBackend`，macOS 用 xattr、Windows 用 NTFS ADS、Linux 用 JSON sidecar
2. 路径拼接统一使用 `PathBuf::join()`，前端使用 `path.join()` 或 Tauri path API
3. "在文件管理器中显示" 使用 `tauri-plugin-shell` 的 `open` API（已内置跨平台）

### 3.5 文件监视

**问题**：`watcher.rs` 使用 `RecursiveMode::NonRecursive`，子目录变更不触发刷新。

**方案**：
1. 改为 `RecursiveMode::Recursive`，但增加深度限制（max_depth=3）防止监视整个磁盘
2. 事件去重 + 防抖：500ms 窗口内同一文件的多次事件合并为一次
3. 对大目录（>10000 文件）自动降级为手动刷新模式，避免 inotify/FSEvents 资源耗尽
4. 前端修复双重订阅问题（删除冗余 useEffect）

**验收目标**：子目录新增文件后 ≤1s 前端列表自动更新

### 3.6 内存占用

**问题**：
- `compress_to_zip` 全量 `read_to_end` 
- `secure_delete_file` 分配与文件等大的随机 buffer
- `diff_files` O(m×n) DP 表
- `library_scan_media` 对每张图片调用 `image::open`

**方案**：
1. ZIP 压缩改用 `zip::ZipWriter` 流式写入，逐块 64KB 读取
2. 安全删除改为分块覆写（每次 1MB buffer 循环写入），恒定内存
3. Diff 改用 `similar` crate（Myers 算法），内存 O(N) 而非 O(N²)
4. 媒体扫描只读文件头获取尺寸（`image::ImageReader::open().into_dimensions()`），不解码全图

**验收目标**：处理 2GB 文件时峰值内存增量 <50MB

### 3.7 并发与竞态

**问题**：
- 多个 watcher 事件同时触发 `loadDirectory`，可能产生过期数据覆盖新数据
- Tab 切换时旧请求未取消，响应到达后设置了错误 tab 的 fileList
- `indexer.rs` load/save 无锁，并发调用可能数据丢失

**方案**：
1. 目录加载增加 request_id 或 generation counter，响应到达时校验是否为最新请求
2. Tab 切换时 abort 前一个 loadDirectory（前端 AbortController 模式）
3. Indexer 使用 `Arc<RwLock<>>` 内存缓存 + 写时 debounce 落盘
4. 前端 fileStore 的 `setFileList` 增加 `expectedPath` 参数，路径不匹配则丢弃

### 3.8 前端架构拆分

**问题**：App.tsx 2249 行，40+ useState，职责不清。

**方案**：
```
src/
├── App.tsx              — 仅路由/布局壳（<100L）
├── features/
│   ├── navigator/       — 目录导航、历史、面包屑
│   ├── file-ops/        — 复制/移动/删除/重命名逻辑
│   ├── preview/         — 预览面板 + QuickLook
│   ├── search/          — 搜索栏 + 高级过滤
│   ├── batch/           — 批量操作进度/取消
│   └── tools/           — 终端/归档/同步等工具面板
├── stores/              — Zustand slices（按 feature 拆分）
└── hooks/               — 通用 hooks（useOperation, useWatcher）
```

每个 feature 目录包含自己的组件、hooks、store slice，通过 App.tsx 组合。

## 数据模型改进建议

### OperationRecord（新增）
```typescript
interface OperationRecord {
  id: string;              // UUID
  type: 'copy' | 'move' | 'trash' | 'delete' | 'rename' | 'compress';
  status: 'pending' | 'running' | 'completed' | 'cancelled' | 'failed';
  items: { src: string; dest?: string; status: 'pending'|'done'|'error'; error?: string }[];
  startedAt: number;
  completedAt?: number;
  undoable: boolean;       // 是否可通过 undo stack 回滚
}
```

### UndoEntry（新增）
```typescript
interface UndoEntry {
  id: string;
  operation: OperationRecord;
  inverseActions: { type: string; params: Record<string, unknown> }[];
  timestamp: number;
}
```

### FileEntry 扩展
```typescript
// 现有 FileEntry 缺少以下字段
interface FileEntry {

  tags?: string[];          // 文件标签（从 tags.json 关联）
}
```

## 量化验收目标

| 指标 | 当前估计 | 目标值 | 假设条件 |
|------|----------|--------|----------|
| 10000 文件目录首次渲染 | >2000ms | <300ms | SSD + 分页加载 |
| 2GB 文件 ZIP 压缩内存峰值 | ~2GB (OOM) | <50MB | 流式写入 |
| 批量 1000 文件移入回收站 | ~30s 不可取消 | ~10s + 可取消 | 并发 4 线程 |
| 文件监视子目录事件延迟 | 不触发 | <1s | RecursiveMode + depth=3 |
| Diff 10000 行文件内存 | ~400MB | <20MB | Myers 算法 |
| 索引搜索响应 | ~800ms (每次 reload) | <50ms | 内存缓存 + SQLite |
| App.tsx 行数 | 2249 | <200 | Feature 拆分后 |
| 前端冷启动到可交互 | 未测量 | <1.5s | 含 Tab 恢复 |
